# `Intl.Locale` normative behavior baseline

Status: research finding for [Establish the normative behavior baseline](https://github.com/MidnightDesign/locale-php/issues/4), retrieved 2026-09-09. This records the current semantic surface and recommends reproducible upstream snapshots. It does **not** choose the product's compatibility promise.

## Current semantic surface

### Construction and option application

`Intl.Locale` must be called with `new`. The `tag` must initially be a String or Object; an initialized `Intl.Locale` contributes its internal canonical locale directly, while another Object is string-coerced. Other primitives throw `TypeError`. `options` is coerced to an Object before tag well-formedness is checked. The object is an ordinary, extensible instance using `newTarget`'s prototype. [constructor algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L13-L77), [Test262 constructor/object fixtures](https://github.com/tc39/test262/tree/419d3e0a2273ba01a3bfcbec423f2801425b8e93/test/intl402/Locale)

The constructor processes these options:

| Concern | Option | Accepted semantic value | Observable effect |
|---|---|---|---|
| language identifier | `language` | UTS #35 `unicode_language_subtag` | Replaces the base language. |
| language identifier | `script` | `undefined` or `unicode_script_subtag` | Replaces/removes the base script. |
| language identifier | `region` | `undefined` or `unicode_region_subtag` | Replaces/removes the base region. |
| language identifier | `variants` | `undefined` or a non-empty, hyphen-separated, duplicate-free sequence of `unicode_variant_subtag` values | Replaces/removes all base variants. |
| Unicode keyword | `calendar` | a syntactic Unicode `type` | Overrides `ca`. |
| Unicode keyword | `collation` | a syntactic Unicode `type` | Overrides `co`. |
| Unicode keyword | `firstDayOfWeek` | a syntactic Unicode `type`; strings `"0"`…`"7"` are converted to `sun`, `mon`, …, `sun` | Overrides `fw`. |
| Unicode keyword | `hourCycle` | `h11`, `h12`, `h23`, or `h24` | Overrides `hc`. |
| Unicode keyword | `caseFirst` | `upper`, `lower`, or `false` | Overrides `kf` when Collator supports that relevant extension key. |
| Unicode keyword | `numeric` | Boolean coercion | Overrides `kn`; true is serialized as a key with no value and the getter is Boolean. |
| Unicode keyword | `numberingSystem` | a syntactic Unicode `type` | Overrides `nu`. |

The option vocabulary, validation, numeric-weekday conversion, and internal extension-key conditions are normative in the pinned [Locale constructor and `UpdateLanguageId`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L13-L164) and [Locale internal-slot declaration](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L183-L187). Syntactic validity is deliberately broader than data availability: for example, a well-formed `calendar`, `collation`, or `numberingSystem` option need not name functionality the implementation actually provides. Test262 covers valid/invalid values, option precedence, coercion and abrupt completion in its [constructor fixtures](https://github.com/tc39/test262/tree/419d3e0a2273ba01a3bfcbec423f2801425b8e93/test/intl402/Locale).

Ordering is observable in JavaScript: canonicalize the input tag; read/coerce language, script, region, and variants to update its language ID; then read/coerce `calendar`, `collation`, `firstDayOfWeek`, `hourCycle`, `caseFirst`, `numeric`, and `numberingSystem`; finally merge/canonicalize Unicode keyword overrides. Options override the corresponding `-u-` keyword while unrelated extensions, Unicode attributes/keywords, and private-use content survive canonicalization. [constructor algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L32-L76), [`MakeLocaleRecord`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L119-L164), [Test262 option-order fixture](https://github.com/tc39/test262/blob/419d3e0a2273ba01a3bfcbec423f2801425b8e93/test/intl402/Locale/constructor-getter-order.js)

For the PHP spec layer, JavaScript property-getter order and built-in property descriptors have no direct representation, but the semantic order still matters whenever PHP objects perform user code during string/Boolean conversion. Such fixtures must be classified by **test intent**; JavaScript scaffolding alone does not make a fixture an **inapplicable test**.

### Well-formedness and canonicalization

ECMA-402 accepts Unicode BCP 47 locale identifiers, not every BCP 47 form and not CLDR's backwards-compatible underscore/`root` forms. Well-formedness lowercases for checking, matches the UTS #35 `unicode_locale_id` grammar, rejects backwards-compatibility syntax, duplicate variants, duplicate non-private-use singleton extensions, and duplicate variants inside a `tlang`; it does not require registered/meaningful subtags, canonical casing, or preferred aliases. A private-use-only tag such as `x-private` is not a Unicode BCP 47 locale identifier. [ECMA-402 language tags and `IsWellFormedLanguageTag`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locales-currencies-tz.html#L19-L66), [UTS #35 BCP 47 conformance](https://www.unicode.org/reports/tr35/tr35-78/tr35.html#BCP_47_Conformance)

Canonicalization first runs UTS #35 Annex C `Processing LocaleIds`, which case-regularizes and applies CLDR alias rules. It then reconstructs the Unicode `u` extension so only the first duplicate attribute and first keyword for a key remain and canonical order/form is returned. Variant order, extension order, aliases such as legacy language/territory codes, and key/type aliases are therefore observable. Canonicalization can alter several subtags at once, which is why the input is canonicalized before language-ID options and the combined result is canonicalized again after Unicode option merging. [ECMA-402 `CanonicalizeUnicodeLocaleId`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locales-currencies-tz.html#L69-L102), [`CanonicalizeUValue`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/negotiation.html#L83-L99), [UTS #35 canonicalization](https://www.unicode.org/reports/tr35/tr35-78/tr35.html#LocaleId_Canonicalization), [CLDR alias source](https://github.com/unicode-org/cldr/blob/11299982335beb974c1c63c45265184e759c0f41/common/supplemental/supplementalMetadata.xml)

### Getters and string form

All accessors require an initialized Locale receiver. `baseName` is the canonical language ID without extensions; `language`, `script`, `region`, and `variants` expose its canonical components, with `undefined` for absent optional components. `calendar`, `collation`, `firstDayOfWeek`, `hourCycle`, and `numberingSystem` expose their canonical Unicode keyword values or `undefined`. `caseFirst` and `numeric` exist only when the implementation's Collator includes `kf` and `kn` respectively; where present, `caseFirst` is its string value or `undefined`, while `numeric` is `true` for empty/`true` `kn` and otherwise `false`. `toString()` returns the complete canonical locale identifier. [pinned getters and `toString`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L207-L348), [instance slot invariants](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L447-L465)

The complete getter set at this pin is: `baseName`, `calendar`, `caseFirst`, `collation`, `firstDayOfWeek`, `hourCycle`, `language`, `numberingSystem`, `numeric`, `region`, `script`, and `variants`. The last two additions relative to ES2025 are `firstDayOfWeek` and `variants`; `variants` also became a constructor option. [ES2025-to-ES2026 source diff](https://github.com/tc39/ecma402/compare/es2025-candidate-2025-04-01...es2026-candidate-2026-04-01#diff-9115b95c94c5a27c152b8154b809afbd125a72789c56c2aa6d6529de30b5b67a), [`variants` normative commit](https://github.com/tc39/ecma402/commit/e8c995a38cfd347c247c046ffbbe46f81b4f285c)

### `maximize()` and `minimize()`

`maximize()` applies UTS #35 Add Likely Subtags; `minimize()` applies Remove Likely Subtags, which first maximizes and then tests removal candidates. Both preserve variants, extensions, and private use, construct and return a fresh `Intl.Locale`, and fall back to the original canonical identifier if the UTS operation signals an error. [ECMA-402 methods](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L278-L298), [UTS #35 likely-subtag algorithms](https://www.unicode.org/reports/tr35/tr35-78/tr35.html#Likely_Subtags), [Test262 vectors](https://github.com/tc39/test262/blob/419d3e0a2273ba01a3bfcbec423f2801425b8e93/test/intl402/Locale/likely-subtags.js)

The algorithm is normative but its mapping data move with CLDR. Consequently, exact maximized/minimized strings are version-sensitive even when two implementations follow the same algorithm. UTS #35 explicitly warns that locale equivalence can change when aliases or likely-subtag mappings change. [UTS #35 canonical/maximal/equivalent identifiers](https://www.unicode.org/reports/tr35/tr35-78/tr35.html#Canonical_Unicode_Locale_Identifiers), [CLDR 44 likely-subtag migration](https://cldr.unicode.org/downloads/cldr-44)

## Locale-information methods

All seven methods brand-check the receiver. Array results are fresh ordinary Arrays; object results are fresh ordinary Objects with the exact enumerable data keys shown below. The underlying abstract operations are explicitly implementation-defined within their stated constraints. [public methods](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L351-L425), [implementation-defined operations](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L620-L920)

| Method | Pinned behavior | Normative/data inputs |
|---|---|---|
| `getCalendars()` | If `ca` is present, return that canonical value alone. Otherwise derive a base region from explicit region, then canonical `sd`, then likely subtags, then `001`; try `rg` override before the base. For each candidate, prefer language-region calendar preferences over region-only data, canonicalize values, retain only `AvailableCalendars()`, de-duplicate in preference order, and fall back to `gregory`. | UTS #35 calendar preference data; CLDR `calendarPreferenceData`; the implementation's DateTimeFormat calendar availability. [algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L620-L652), [CLDR source](https://github.com/unicode-org/cldr/blob/11299982335beb974c1c63c45265184e759c0f41/common/supplemental/supplementalData.xml) |
| `getCollations()` | If `co` is present, return it alone. Otherwise prefix-match the Locale against Collator available locales, take that locale's supported non-default `co` values, and code-unit sort them. If no locale matches, return `['emoji', 'eor']`; do not consult the host default locale. | The implementation's Collator `AvailableLocales` and `SortLocaleData.[[co]]`; CLDR/UCA tailoring availability typically supplies it. [algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L654-L677), [Collator data constraints](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/collator.html#L82-L108) |
| `getHourCycles()` | If `hc` is present, return it alone. Otherwise use the same region/`sd`/likely/`rg` candidate logic as calendars and prefer language-region time data before region-only data. Return unique preference-ordered members of `h11`, `h12`, `h23`, `h24`; fall back to `h23`. | UTS #35 time data and CLDR `timeData`. [algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L679-L705), [UTS #35 Time Data](https://www.unicode.org/reports/tr35/tr35-78/tr35-dates.html#Time_Data) |
| `getNumberingSystems()` | If `nu` is present, return it alone. Otherwise prefix-match NumberFormat available locales and return only the first/default supported `nu`; fall back to `latn`. | The implementation's NumberFormat `AvailableLocales` and `LocaleData.[[nu]]`, commonly derived from CLDR number data. [algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L707-L728), [NumberFormat data constraints](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/numberformat.html#L233-L268) |
| `getTimeZones()` | Use only an explicitly present region subtag. With no explicit region, return `undefined`; do not maximize and do not apply `rg`/`sd`. Otherwise return unique IANA canonical Zone names in common use in that region, code-unit sorted; an empty Array is permitted. | IANA tzdb names, casing, Zone/Link identity and region association, plus ECMA-402 primary-ID rules. [Locale algorithm](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L730-L744), [ECMA-402 IANA rules](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locales-currencies-tz.html#L152-L300) |
| `getTextInfo()` | Return `{ direction }`. Use an explicit script, otherwise Add Likely Subtags; return `rtl` or `ltr` from the script's default line direction, or `undefined` if it cannot be determined. This is fallback metadata, not a claim about every text in the language/script. | UTS #35 script metadata and likely subtags. [public/object algorithm and direction operation](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L401-L411), [direction algorithm and caveat](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L746-L773) |
| `getWeekInfo()` | Return exactly `{ firstDay, weekend }`; there is no `minimalDays` field at this pin. Choose `rg` data if available, otherwise the RegionPreference base region, otherwise `001`; `fw` overrides `firstDay`. Days are ISO Monday=`1` through Sunday=`7`, and `weekend` is a non-empty ascending list which may be non-contiguous. | UTS #35 week data, first-day overrides, region aliases, likely subtags, and `rg`/`sd` key semantics. [algorithm/result shape](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L866-L920), [UTS #35 Week Data](https://www.unicode.org/reports/tr35/tr35-78/tr35-dates.html#Week_Data) |

`RegionPreference` is shared by calendars, hour cycles, and week info: explicit region wins over `sd`; a valid canonical subdivision supplies a region only when the language ID lacks one; likely subtags are next; `001` is last; `rg` is a separate override candidate. Time zones intentionally do not call it. [pinned `CanonicalUnicodeSubdivision` and `RegionPreference`](https://github.com/tc39/ecma402/blob/b1c961988b9a07894b1dc3dc2b5626ea48387d61/spec/locale.html#L577-L618)

## Reproduction checklist

1. Fetch the two full commit SHAs above and verify the ECMA `spec/` tree, Locale source blob/SHA-256, and Test262 Locale subtree IDs.
2. Enumerate Test262 fixtures with `git ls-tree -r --name-only 419d3e0a2273ba01a3bfcbec423f2801425b8e93 -- test/intl402/Locale`, filtering `.js`; expect 168.
3. Parse Test262 frontmatter and retain both `Intl.Locale` and `Intl.Locale-info` feature tags; do not equate JavaScript translation limitations with test intent.
4. Record the exact CLDR/UTS #35, IANA language-registry, tzdb, and any ICU revisions used to generate or verify the release's data tables. Do not let the host's ICU silently redefine outputs.
5. At a baseline upgrade, diff ECMA-402 `spec/locale.html`, `spec/locales-currencies-tz.html`, and the relevant service-locale-data constraints; diff the complete Test262 Locale subtree; regenerate data tables; then review changed golden vectors separately from algorithm changes.

This procedure defines what was verified while leaving the product free to track newer revisions during development, which is the repository's meaning of **conformance baseline**.
