# Conformance and release data

This package is not yet ECMA-402 conformant. Locale identifier construction, canonical properties, likely-subtag methods, and primary time-zone lookup are implemented; other locale-information methods remain incomplete.

The current conformance baseline pins ECMA-402 at `b1c961988b9a07894b1dc3dc2b5626ea48387d61` and Test262 at `419d3e0a2273ba01a3bfcbec423f2801425b8e93`. [The Test262 baseline manifest](../tests/Test262/baseline.json) separates these immutable initial revisions from the active tracked inputs. Advancing the active inputs compares them with [the immutable initial inventory](../tests/Test262/initial-inventory.json) and generates a stable record of added, changed, and removed fixtures and assertion identities; repeated generation does not erase that comparison. [The release data manifest](../resources/data/manifest.json) records the exact Unicode 17.0.0, CLDR 48.2, IANA registry dated 2026-08-08, and tzdb 2026c inputs with complete hashes, notices, generator fingerprints, and the release data fingerprint.

Pinned Test262 originals used by generated scripts live under `tests/Test262/upstream`. The directory also preserves the pinned Test262 and ECMA-402 license notices. Each translated fixture produces one plain PHP script under `tests/Test262/Generated`, preserving its upstream-relative path. Generated PHP translations retain both source revisions and paths, and `composer test262:check` proves byte-for-byte regeneration.

`composer test262:run` executes the scripts through the single handwritten `tests/Test262/RunnerTest.php` integration point. PHPUnit reports each script as a named data set whose identity is the upstream-relative `.js` path. Run one fixture directly with `php vendor/bin/phpunit --testsuite test262-upstream --filter 'test/intl402/Locale/getters-missing.js'`. Each fixture's conformance evidence records its generated script paths, PHPUnit identities, and optional representation variants as the canonical execution manifest. The runner cross-checks that manifest against the generated tree, so missing, stale, or duplicate scripts fail before execution. Regeneration stages the complete script tree and evidence together and restores the previous output if publication fails. The [PHPUnit integration decision](research/phpunit-test262-runner.md) records why the supported named-data-provider mechanism was selected over dynamic suite registration.

[The translated evidence](../tests/Test262/evidence.json) records the verified upstream source and license identities, assertion adaptations, required PHP representations, and execution results. The original `constructor-options-script-valid.js` fixture runs 30 generated checks: its three source assertions expand across five upstream cases and both associative-array and plain-object option bags without being counted as 30 upstream assertions. Each check remains tied to its original source assertion.

[The complete pinned Locale corpus inventory](../tests/Test262/corpus.json) keeps all 168 upstream fixtures and all 485 standard Test262 assertion expressions visible with stable source locations and expression hashes. A fixture-level gap also covers parameterized executions and custom helper behavior until translated evidence accounts for them. Translation gaps, incomplete inventory entries, and execution failures make the machine-readable conformance claim ineligible. Every generator run also writes the current result to `build/test262-results.json`, including failures that differ from the committed evidence. A translation gap remains unfinished work and does not count as a pass.

`composer data:verify-sources -- <UCD.zip> <cldr-core.zip> <language-subtag-registry> <tzdata.tar.gz>` verifies every complete upstream input and the registry date before generation. `composer data:check` verifies that the independently generated alias, likely-subtag, and primary-time-zone projections are byte-identical and match the recorded source, generated, generator, and complete-snapshot fingerprints. Upstream archives are generator inputs and are not shipped. Locale construction verifies the alias payload before using it; likely-subtag operations and `getTimeZones()` verify their separate generated payloads on demand. All public results come from bundled PHP code and static data. Host ICU, ambient locale and time-zone defaults, network access, and writable storage do not define results.

Release maintainers regenerate the time-zone source projection with `composer data:import-time-zones -- <tzdata.tar.gz> <cldr-core.zip>` after the complete archives pass verification. The importer reads every current tzdb Zone and Link, `zone.tab`, and `backzone`, applies the ECMA-402 primary-ID exceptions and the reviewed rename waiting-period decision, then emits only identifiers, primary mappings, and region lists—never transition data.

The translated likely-subtag corpus covers the original pinned maximization, minimization, preservation, fallback, grandfathered-tag, branding, name, and arity assertions. JavaScript-only property descriptor flags are recorded as inapplicable PHP adaptations. The pinned corpus lacks assertions that operations on a subclass return a base `Intl.Locale`, tracked by [issue #49](https://github.com/MidnightDesign/locale-php/issues/49); that unknown placeholders and transformed extensions are handled correctly, tracked by [issue #50](https://github.com/MidnightDesign/locale-php/issues/50); and that removal returns the maximized identifier when no minimization candidate matches, tracked by [issue #51](https://github.com/MidnightDesign/locale-php/issues/51). These tickets require upstream Test262 contributions and later baseline updates. No custom spec-layer test substitutes for those upstream obligations.
